# Практическая работа #6: Агрегация и объединение таблиц в SQL (COUNT, SUM, AVG, MIN, MAX, GROUP BY, HAVING, INNER/LEFT JOIN)

## 1. Цель работы
Освоить аналитический инструментарий реляционных СУБД для построения сводных бизнес-отчетов и извлечения связанных данных:
1. Вычисление базовых статистик через агрегатные функции: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.
2. Понимание поведения `NULL`-значений в агрегатах (все агрегатные функции, кроме `COUNT(*)`, строго игнорируют `NULL`).
3. Группировка строк по категориальным признакам (`GROUP BY`).
4. Постизоляционная фильтрация вычисленных групп (`HAVING`) и четкое понимание разницы между `WHERE` и `HAVING`.
5. Понимание физического порядка выполнения инструкций движком SQLite:  
   `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` → `LIMIT`.
6. Соединение нормализованных таблиц: внутреннее соединение (`INNER JOIN`) и левое внешнее соединение (`LEFT JOIN`).
7. Поиск несвязанных сущностей («спящие» клиенты, простаивающее оборудование) через паттерн `LEFT JOIN ... WHERE right.key IS NULL`.
8. Комбинирование связок `JOIN` + `GROUP BY` + `HAVING` для агрегации данных из нескольких источников в единую витрину.

## 3. Лекторский минимум и золотые правила SQL

1. **Агрегатам не место в `WHERE`:**  
   Фильтрация `WHERE COUNT(*) > 5` — грубая ошибка. Условие `WHERE` работает **до** того, как строки собрались в группы. Любые проверки вычисленных показателей (`COUNT`, `AVG`, `SUM`) пишутся строго в блоке `HAVING`.
2. **Правило столбцов в `GROUP BY`:**  
   Каждое поле, указанное в блоке `SELECT`, обязано либо входить в перечень `GROUP BY`, либо быть обернуто в агрегатную функцию (`SUM`, `AVG`, `MAX` и т.д.).
3. **`COUNT(*)` против `COUNT(column)`:**  
   * `COUNT(*)` считает абсолютное число строк в группе (включая `NULL`).  
   * `COUNT(column)` считает только строки, где в указанном столбце есть реальное значение (пропуски `NULL` игнорируются).
4. **Опасность `WHERE` при `LEFT JOIN`:**  
   Если после `LEFT JOIN` написать в `WHERE` условие на правую таблицу (например, `WHERE p.status = 'Active'`), строки с `NULL` отсекутся, и `LEFT JOIN` автоматически превратится в обычный `INNER JOIN`. Дополнительные фильтры правой таблицы в левом соединении задаются внутри секции `ON`!
5. **Поиск «сирот»:**  
   Классический паттерн поиска записей без пары:  
   `LEFT JOIN dependent_table ON ... WHERE dependent_table.id IS NULL`.
6. **Параметризация:**  
   Все пороговые значения (число сессий, средний чек, лимиты) передаются в запрос через кортеж параметров и символ `?`.
