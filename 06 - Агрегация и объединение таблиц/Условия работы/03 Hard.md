# Практическая работа #6: Уровень 3 (Продвинутый / Hard)

## 1. Описание набора данных
В папке вашего варианта (`hard/variant_XX/`) представлены три CSV-файла (разделитель — точка с запятой `;`):

* `hardware_pcs.csv` — парк игрового оборудования клуба (40 компьютеров):
  * `pc_id` — первичный ключ ПК;
  * `pc_number` — инвентарный номер (`PC-01`...);
  * `zone_name` — зона посадки (`Standard`, `Bootcamp`, `VIP`, `PS5`);
  * `hourly_rate` — тариф за час (руб.);
  * `gpu` — видеокарта;
  * `cpu` — процессор;
  * `ram_gb` — объем ОЗУ;
  * `status` — эксплуатационный статус (`Active`, `Maintenance`, `Reserved`).

* `members.csv` — реестр клиентов клуба (200 клиентов):
  * `member_id` — уникальный номер аккаунта;
  * `nickname` — игровой псевдоним;
  * `city` — город регистрации;
  * `email` — электронный адрес (часть значений `NULL`);
  * `registered_at` — дата регистрации (`YYYY-MM-DD`);
  * `loyalty_tier` — уровень карты лояльности (`Bronze`, `Silver`, `Gold`, `Platinum`);
  * `balance` — остаток на клубном депозите (руб.).

* `game_sessions.csv` — журнал игровых сессий (800 записей):
  * `session_id` — номер сессии;
  * `member_id` — ID игрока (для анонимных визитов значение равно `NULL`);
  * `pc_id` — ID рабочей станции;
  * `game_title` — запущенная игра;
  * `session_date` — таймштамп сессии (`YYYY-MM-DD HH:MM:SS`);
  * `hours_played` — время игры (ч);
  * `discount_promo` — флаг скидки (1 / 0);
  * `total_paid` — итоговая сумма к оплате (руб.);
  * `client_rating` — оценка сервиса (от 1 до 5 звезд, часть значений `NULL`).

## 2. Задания к выполнению

### Часть 1. Архитектура схемы и импорт данных (CSV → SQLite)
1. Считайте CSV-файлы в Pandas DataFrame.
2. Инициализируйте файл базы данных `club_hard.db` через `sqlite3.connect()`.
3. Включите строгий контроль ссылочной целостности: `conn.execute("PRAGMA foreign_keys = ON;")`.
4. Спроектируйте схему DDL через `CREATE TABLE` с корректными связями по внешним ключам:
   * `game_sessions.member_id` $\to$ `members(member_id)`;
   * `game_sessions.pc_id` $\to$ `hardware_pcs(pc_id)`.
5. Выполните импорт через `.to_sql(..., if_exists='append', index=False)`.
6. Проведите валидационный аудит строк: сопоставьте `COUNT(*)` из каждой таблицы базы с длиной датафреймов в Pandas.

### Часть 2. Продвинутые агрегаты и когортный аудит
1. **Сводный дашборд показателей клуба:**  
   Одним SQL-запросом к таблице сессий рассчитайте:
   * общее число сессий;
   * суммарную выручку клуба;
   * средний чек за сессию;
   * число уникальных обслуженных клиентов (`COUNT(DISTINCT member_id)`);
   * число фактически задействованных ПК (`COUNT(DISTINCT pc_id)`);
   * среднюю оценку удовлетворенности по оставленным отзывам (`AVG(client_rating)`).
2. **Сравнительный анализ: зарегистрированные гости vs Анонимы:**  
   Сравните два сегмента гостей (по условию `member_id IS NOT NULL` и `member_id IS NULL`):
   * долю в общей выручке клуба;
   * среднюю длительность сессии;
   * среднюю стоимость одного часа игры.

### Часть 3. Многомерная группировка и динамический бенчмарк в `HAVING`
1. **Многомерный срез (Зона × Уровень лояльности):**  
   Объедините `game_sessions`, `hardware_pcs` и `members`.  
   Выполните группировку одновременно по двум полям: `GROUP BY p.zone_name, m.loyalty_tier`.  
   Рассчитайте: количество сессий, суммарную выручку и средний чек. Отфильтруйте группы, где состоялось **не менее 3 сессий**, и отсортируйте по выручке по убыванию.
2. **Динамический бенчмарк (фильтрация по подзапросу в `HAVING`):**  
   Найдите игры, чей средний чек **строго выше среднего чека по всему клубу в целом**.  
   *Требование:* средний чек по клубу не должен быть захардкожен числом — используйте подзапрос:  
   `HAVING AVG(total_paid) > (SELECT AVG(total_paid) FROM game_sessions)`.
3. **Экономика клиентских рангов:**  
   Сгруппируйте клиентов по уровню лояльности (`loyalty_tier`). Рассчитайте метрику LTV/ARPU (суммарный доход, деленный на число уникальных клиентов в данном ранге).

### Часть 4. Сложные соединения и эмуляция `FULL OUTER JOIN`
1. **Аудит премиальных сессий:**  
   Постройте запрос со связкой трех таблиц. Найдите сессии в зонах `'VIP'` и `'Bootcamp'` длительностью **от 3 часов и более**, где клиенты поставили оценку **5 звезд**. Выведите никнейм, город, номер ПК, название игры и сумму чека.
2. **Двусторонний поиск несвязанных элементов:**  
   * Запрос 1: найдите все ПК, на которых не было ни одной игровой сессии (`LEFT JOIN` от `hardware_pcs`).  
   * Запрос 2: найдите всех зарегистрированных клиентов, которые ни разу не играли в клубе (`LEFT JOIN` от `members`).
3. **Эмуляция `FULL OUTER JOIN` в SQLite:**  
   *Проблема:* SQLite нативно не поддерживает конструкцию `FULL OUTER JOIN`.  
   *Задача:* получите полный сводный реестр взаимосвязи клиентов и игровых сессий, включающий:
   * Все зарегистрированные сессии клиентов (`INNER JOIN`);
   * Всех зарегистрированных клиентов без сессий («спящие» клиенты со значениями сессии `NULL`);
   * Все анонимные сессии без привязки к аккаунту (`member_id IS NULL` со значениями клиента `NULL`).  
   *Реализация:* используйте связку `LEFT JOIN` и `UNION ALL` с выборкой анонимных записей.
