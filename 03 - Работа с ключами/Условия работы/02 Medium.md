# Практическая работа #3: Уровень 2 (Средний / Medium)

## Описание набора данных
В папке вашего варианта (`medium/variant_XX/`) представлены два CSV-файла (разделитель — точка с запятой `;`):
* `sessions_with_specs.csv` — денормализованный журнал сессий:
  * `session_id` — номер сессии;
  * `user_id` — идентификатор клиента;
  * `pc_id` — идентификатор компьютера;
  * `pc_zone` — зона клуба;
  * `hardware_specs` — ненормализованная строка формата JSON, содержащая характеристики ПК (`gpu`, `cpu`, `ram_gb`, `monitor_hz`);
  * `date` — дата и время начала игры;
  * `hours_played` — длительность сессии в часах;
  * `extra_bar_spent` — сумма дополнительных трат в баре клуба (руб.);
  * `total_paid` — базовая сумма оплаты за аренду ПК (руб.);
  * `discount_promo` — флаг применения скидочного промокода (1 / 0).
* `users.csv` — справочник клиентов клуба:
  * `user_id` — уникальный идентификатор клиента;
  * `birth_date` — дата рождения;
  * `gender` — пол (`M` / `F`);
  * `loyalty_tier` — уровень карты лояльности (`Bronze`, `Silver`, `Gold`, `Platinum`).

## Задания к выполнению

### 1. Декомпозиция и нормализация схемы данных
1. Загрузите исходные данные.
2. Извлеките характеристики оборудования из текстового поля `hardware_specs` и сформируйте отдельный нормализованный справочник компьютеров `dim_pcs` (`pc_id`, `pc_zone`, `gpu`, `cpu`, `ram_gb`, `monitor_hz`), устранив повторы записей.
3. Убедитесь в уникальности первичного ключа `pc_id` в созданном справочнике.
4. Очистите исходный журнал сессий от избыточных характеристик ПК, сохранив внешний ключ `pc_id`. Полученную таблицу назовите `fact_sessions`.

### 2. Аудит ссылочной целостности через 4 типа объединений
1. **Левое соединение (`left`):**
   * Соедините `fact_sessions` и `users` по ключу `user_id`.
   * Определите количество сессий с нарушением ссылочной целостности («битые» внешние ключи — идентификатор пользователя указан, но отсутствует в справочнике `users`).
   * Определите количество сессий, сыгранных анонимно (идентификатор пользователя отсутствует).
   * Заполните пропуски в демографических атрибутах для сессий без подтвержденного профиля фиктивными значениями (`Guest`, `Unknown`) для возможности последующей обработки.
2. **Внутреннее соединение (`inner`):**
   * Соедините сессии и пользователей только по подтвержденным записям.
   * Рассчитайте совокупную выручку каждой сессии (аренда ПК плюс расходы в баре).
   * Определите средний чек сессии для каждого уровня программы лояльности.
3. **Правое соединение (`right`):**
   * Объедините сессии и справочник пользователей так, чтобы сохранить всех зарегистрированных клиентов.
   * Выявите клиентов, не совершивших ни одной сессии за отчетный месяц (потенциальный отток), и оцените их распределение по уровням лояльности.
4. **Полное внешнее соединение (`outer`):**
   * Сформируйте сводную матрицу ссылочной целостности базы, разделив все записи на три категории:
     1. Подтвержденные сессии зарегистрированных клиентов.
     2. Сессии без подтвержденного профиля (анонимы и «битые» ключи).
     3. Зарегистрированные клиенты без визитов.

### 3. Анализ активности клиентов и зон посадки
1. Объедините очищенную таблицу сессий со справочниками клиентов и компьютеров.
2. Определите топ-5 самых активных клиентов клуба по суммарно проведенному игровому времени за месяц.
3. Выясните, в каких зонах клуба и за какими видеокартами чаще всего играют эти активные клиенты.
4. Сравните средние расходы гостей на бар (`extra_bar_spent`) по зонам клуба: в какой зоне средний чек на бар максимален?
