# Практическая работа #5: Редактирование SQL таблиц (DDL, ограничения целостности, DML: INSERT, UPDATE, DELETE, транзакции)

## 1. Цель работы
Цель работы — освоить проектирование реляционных схем баз данных и управление жизненным циклом данных средствами языка SQL:
1. Создание таблиц (`CREATE TABLE`) со строгими ограничениями целостности (`PRIMARY KEY`, `NOT NULL`, `UNIQUE`, `CHECK`, `DEFAULT`, `FOREIGN KEY`).
2. Включение механизма ссылочной целостности SQLite (`PRAGMA foreign_keys = ON;`) и обработка ошибок валидации (`sqlite3.IntegrityError`).
3. Параметризованная вставка данных (`INSERT INTO ... VALUES (?, ...)`).
4. Безопасная модификация существующих записей (`UPDATE ... SET ... WHERE ...`).
5. Корректное удаление данных (`DELETE FROM ... WHERE ...`) с учетом внешних ключей и каскадных ограничений.
6. Управление транзакциями: обеспечение принципа неделимости операций через `COMMIT` и откат при ошибках через `ROLLBACK`.

---

## 2. Организация данных и уровни сложности

Работа построена по сквозному принципу: **все ключевые темы теории (от DDL до транзакций) отрабатываются на каждом уровне сложности**, но различаются числом сущностей, ветвистостью условий и глубиной бизнес-логики:

* **Уровень 1 (Easy / Базовый):** 2 связанные таблицы (`members` и `game_sessions`). Прямолинейные условия: создание схемы с 1 связью `FOREIGN KEY`, точечные тесты ограничений, базовые команды `UPDATE` и `DELETE`, простая двухшаговая транзакция с фиксированной суммой (`COMMIT` и `ROLLBACK`).
* **Уровень 2 (Medium / Средний):** 3 связанные таблицы (`hardware_pcs`, `members`, `game_sessions`). Схема с двумя внешними ключами: массовые обновления по составным условиям, защита от удаления родительских строк (`RESTRICT`), динамический расчет стоимости аренды в транзакции.
* **Уровень 3 (Hard / Продвинутый):** 3 связанные таблицы с каскадным удалением (`ON DELETE CASCADE`). Сложная транзакция со связыванием тарифов ПК и списанием депозита, проверка автоматической каскадной очистки зависимых строк, аналитический `UPDATE` со сложным условием.

## 3. Лекторский минимум и ключевые правила безопасности

1. **Включение внешних ключей:**
   В SQLite контроль внешних ключей по умолчанию отключен. При каждом новом соединении обязательно выполняется:
   ```python
   conn.execute("PRAGMA foreign_keys = ON;")
   ```
2. **Параметризация запросов:**
   Все динамические значения передаются **исключительно** через подстановочные знаки `?`. Формирование SQL-запросов через f-строки или конкатенацию запрещено.
3. **Обязательность фильтра `WHERE`:**
   Команды `UPDATE` и `DELETE` без блока `WHERE` изменяют или стирают **все** строки таблицы.
4. **Фиксация транзакций:**
   Команды DML (`INSERT`, `UPDATE`, `DELETE`) не сохраняются на диске до вызова `conn.commit()`.
5. **Откат при сбое:**
   Если в цепочке связанных действий происходит ошибка, вызывается `conn.rollback()`, отменяющий все незафиксированные изменения.
6. **Даты:**
   Все даты и временные метки записываются строго в стандарте ISO 8601 (`YYYY-MM-DD` или `YYYY-MM-DD HH:MM:SS`).
