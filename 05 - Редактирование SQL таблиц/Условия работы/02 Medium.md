# Практическая работа #5: Уровень 2 (Medium / Средний)

## 1. Ваши исходные файлы
В папке вашего варианта (`medium/variant_XX/`) лежат три CSV-файла с разделителем `;`:
* `hardware_pcs.csv` — парк компьютеров (`pc_id`, `pc_number`, `zone_name`, `hourly_rate`, `gpu`, `status`).
* `members.csv` — клиенты клуба (`member_id`, `nickname`, `email`, `city`, `balance`, `registered_at`).
* `game_sessions.csv` — сессии (`session_id`, `member_id`, `pc_id`, `game_title`, `start_time`, `duration_hours`, `status`, `client_rating`).

---

## 2. Что нужно сделать

### Задание 1. Проектирование схемы с двумя внешними ключами (DDL)
1. Подключитесь к файлу `club_medium.db` и включите контроль связей:
   ```python
   conn = sqlite3.connect("club_medium.db")
   conn.execute("PRAGMA foreign_keys = ON;")
   ```
2. Создайте родительские таблицы `hardware_pcs` и `members`:
   * В `hardware_pcs`: первичный ключ, уникальный номер ПК `pc_number`, ограничение зон `CHECK (zone_name IN ('Standard', 'Bootcamp', 'VIP', 'PS5'))`, положительный тариф `CHECK (hourly_rate > 0)` и статус по умолчанию `'Active'`.
   * В `members`: первичный ключ, уникальный никнейм, уникальный email, ограничение неотрицательного баланса `CHECK (balance >= 0)`.
3. Создайте дочернюю таблицу `game_sessions` с двумя связями:
   * Внешний ключ на клиента: `FOREIGN KEY (member_id) REFERENCES members(member_id)`;
   * Внешний ключ на компьютер: `FOREIGN KEY (pc_id) REFERENCES hardware_pcs(pc_id)`;
   * Ограничение длительности: `CHECK (duration_hours > 0 AND duration_hours <= 24)`;
   * Ограничение оценки сервиса: `CHECK (client_rating BETWEEN 1 AND 5)`;
   * Статус сессии со значениями `'active'`, `'completed'`, `'cancelled'` (по умолчанию `'active'`).

### Задание 2. Импорт данных из CSV
1. Прочитайте CSV-файлы через `pd.read_csv("...", sep=";")`.
2. Загрузите данные в таблицы через `.to_sql(..., if_exists="append", index=False)`.
   * **Порядок загрузки:** сначала родительские таблицы (`hardware_pcs`, `members`), затем дочерняя (`game_sessions`). Попробуйте мысленно поменять порядок — почему SQLite выдаст ошибку?
3. Зафиксируйте сохранение: `conn.commit()`.

### Задание 3. Тестирование целостности связей и ограничений
Оформите каждую проверку через `try ... except sqlite3.IntegrityError:`:
1. **Тест внешнего ключа:** попытка создать сессию с несуществующим ПК (`pc_id = 99999`).
2. **Тест диапазона CHECK:** попытка выставить оценку `client_rating = 10`.
3. **Тест UNIQUE:** попытка добавить компьютер с уже существующим инвентарным номером `pc_number`.

### Задание 4. Массовые и расчетные обновления (UPDATE)
1. **Массовое закрытие старых сессий:** переведите все сессии в статусе `'active'`, начатые ранее `'2026-03-01'`, в статус `'completed'`. Выведите число обновленных строк через `cur.rowcount`.
2. **Индексация тарифов:** поднимите часовой тариф всех компьютеров зоны `'VIP'` на 10% с округлением до целых:
   ```sql
   UPDATE hardware_pcs
   SET hourly_rate = ROUND(hourly_rate * 1.10)
   WHERE zone_name = 'VIP';
   ```
3. Зафиксируйте изменения (`conn.commit()`) и покажите результат выборкой `SELECT`.

### Задание 5. Удаление данных и ссылочная защита (DELETE)
1. **Очистка отмененных записей:** посчитайте число сессий со статусом `'cancelled'`, удалите их запросом `DELETE FROM game_sessions WHERE status = 'cancelled';` и через `SELECT COUNT(*)` убедитесь, что их больше нет.
2. **Защита родительской записи:** выберите `pc_id` компьютера, за которым уже числятся игровые сессии. Попробуйте удалить этот ПК из таблицы `hardware_pcs`. В блоке `try ... except` убедитесь, что СУБД блокирует операцию (`FOREIGN KEY constraint failed`).

### Задание 6. Транзакция с динамическим расчетом стоимости (COMMIT и ROLLBACK)
Стоимость аренды рассчитывается по формуле: `сумма = duration_hours * 150`.

1. **Успешная оплата (COMMIT):**
   * Выберите активную сессию клиента, чей баланс покрывает расчетную стоимость.
   * В одной транзакции спишите сумму с баланса клиента и переведите сессию в статус `'completed'`.
   * Зафиксируйте транзакцию (`conn.commit()`) и выведите результат через `SELECT`.
2. **Откат при нехватке депозита (ROLLBACK):**
   * Найдите сессию клиента, чей баланс меньше расчетной стоимости.
   * Начните операцию списания в блоке `try ... except`. Из-за срабатывания `CHECK (balance >= 0)` база выбросит ошибку.
   * В блоке ошибки вызовите `conn.rollback()`.
   * Докажите через `SELECT`, что данные не пострадали (баланс прежний, статус сессии активный).
3. Закройте соединение `conn.close()`.
