# Практическая работа #5: Уровень 1 (Easy / Базовый)

## 1. Ваши исходные файлы
В папке вашего варианта (`easy/variant_XX/`) лежат два CSV-файла с разделителем `;`:
* `members.csv` — клиенты клуба (`member_id`, `nickname`, `email`, `city`, `balance`, `registered_at`).
* `game_sessions.csv` — игровые сессии (`session_id`, `member_id`, `game_title`, `start_time`, `hours_played`, `status`).

---

## 2. Что нужно сделать

### Задание 1. Создание базы данных и проектирование схемы (DDL)
1. Подключитесь к файлу `club_easy.db` и сразу включите контроль связей:
   ```python
   conn = sqlite3.connect("club_easy.db")
   conn.execute("PRAGMA foreign_keys = ON;")
   ```
2. Создайте таблицу клиентов `members` со следующими правилами:
   * `member_id` — целочисленный первичный ключ (`PRIMARY KEY`);
   * `nickname` — обязательный (`NOT NULL`) и уникальный (`UNIQUE`) текст;
   * `email` — уникальный текст (может быть пустым / `NULL`);
   * `city` — текст со значением по умолчанию `'Москва'`;
   * `balance` — вещественное число, по умолчанию `0`, с ограничением `CHECK`, запрещающим отрицательные значения;
   * `registered_at` — дата со значением по умолчанию `CURRENT_DATE`.
3. Создайте связанную таблицу сессий `game_sessions`:
   * `session_id` — первичный ключ;
   * `member_id` — обязательное целое число, внешний ключ (`FOREIGN KEY`), ссылающийся на `member_id` таблицы `members`;
   * `game_title` — обязательный текст;
   * `start_time` — обязательный текст (дата и время ISO);
   * `hours_played` — вещественное число, строго больше 0 (`CHECK`);
   * `status` — текст по умолчанию `'active'`, допустимы только значения `'active'` или `'completed'` (`CHECK`).

### Задание 2. Импорт данных из CSV
1. Прочитайте CSV-файлы вашего варианта через `pd.read_csv("...", sep=";")`.
2. Загрузите данные в таблицы базы через метод `.to_sql()`. 
   * **Важно:** используйте параметр `if_exists="append"`, чтобы не стереть созданную схему!
   * **Порядок имеет значение:** подумайте, какую таблицу нужно заполнить первой — клиентов или сессии? Что произойдет, если попытаться сначала загрузить сессии?
3. Зафиксируйте изменения: `conn.commit()`.

### Задание 3. Тестирование защиты базы (IntegrityError)
Каждую проверку оберните в блок `try ... except sqlite3.IntegrityError:` и выведите текст пойманной ошибки:
1. **Тест CHECK:** попробуйте вставить сессию с отрицательным временем (`hours_played = -2`).
2. **Тест FOREIGN KEY:** попробуйте вставить сессию для несуществующего клиента (`member_id = 99999`).
3. **Тест UNIQUE:** попробуйте добавить клиента с никнеймом, который уже занят.

### Задание 4. Изменение данных (UPDATE)
Перед изменением покажите строку через `SELECT`, обновите данные с параметром `?`, сделайте `conn.commit()` и покажите строку после изменения:
1. Пополните баланс клиента `member_id = 1` на `300` рублей.
2. Для активной сессии с `session_id = 1005` измените статус на `'completed'`.

### Задание 5. Удаление данных и проверка защиты (DELETE)
1. Удалите одну завершенную сессию по ее номеру (`session_id`). Убедитесь через `SELECT COUNT(*)`, что количество сессий уменьшилось на 1.
2. Попробуйте удалить из таблицы `members` клиента, у которого есть сыгранные сессии. В блоке `try ... except` убедитесь, что СУБД запрещает удаление (`FOREIGN KEY constraint failed`).

### Задание 6. Управление транзакциями (COMMIT и ROLLBACK)
Моделируем списание фиксированной стоимости аренды (`200` руб.) и закрытие сессии:
* Шаг 1: списать 200 руб. с баланса клиента (`UPDATE members ...`).
* Шаг 2: перевести сессию в статус `'completed'` (`UPDATE game_sessions ...`).

1. **Успешная транзакция:**
   * Найдите активную сессию клиента, у которого на балансе **больше или равно 200 руб.**
   * Выполните оба шага и зафиксируйте результат через `conn.commit()`.
   * Выведите строки через `SELECT`, подтвердив списание и закрытие сессии.
2. **Откат при сбое:**
   * Найдите сессию клиента, у которого на балансе **строго меньше 200 руб.**
   * Запустите операцию в блоке `try ... except`. Попытка вычесть 200 рублей вызовет ошибку `CHECK (balance >= 0)`.
   * В блоке `except` вызовите `conn.rollback()`.
   * Через `SELECT` докажите, что база вернулась в исходное состояние: деньги не списались, сессия осталась активной.
3. Закройте соединение `conn.close()`.
